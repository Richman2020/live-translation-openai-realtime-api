## 一个通话记录所需的事实

首轮仍是一个 controller、一个活动通话、一个 warm 实例。持久端口至少需要
在一个可核对的通话记录中保留下列事实；可拆表，但关联写入须具有明确事务边界。

| 事实 | 最小内容与约束 |
| --- | --- |
| 通话及授权绑定 | 服务器 call ID、已验证 authSession/principal/browserOwner 与 auth epoch、tab、controller epoch、lease 引用、每通 identity、固定供应商账户/应用及 callback 绑定。旧 epoch 不能因重启变成当前控制权 |
| 预算与创建 intent | reservation ID、服务器生成的幂等操作键、call ID、预留上限及适用预算规则、当前许可状态/截止时间、版本。预算预留和创建 intent 同一次事务提交，不能只写其中一项 |
| 签发与 join | 签名操作键、授权描述摘要、签发/最晚有效期限、签发结果是否未知、一次性 join 绑定与消费状态、所消费的 browser SID。凭证不得进入日志；恢复校验所需秘密或摘要的保存方式留给实际适配器设计 |
| 两腿与供应商操作 | local/remote 各自的创建意图、操作键、已验证 SID、已知状态及终态证据；没有 SID 的创建结果未知也须单独保存，不能记成“未创建” |
| 结束与责任 | 同步结束 intent、清理待办/重试结果、全部已知 SID 的终态确认、未知创建是否核对完成、票据/供应商迟到窗口、预算结算状态和版本。结束记录必须能在浏览器及登录失效后独立恢复 |

幂等键由服务端生成并关联已有 call/操作；客户端重复点击不能产生新的预算或
第二个 dial。join 消费和 browser SID 绑定须原子完成：同 SID 的已签名重试只
返回原结果；新 SID、跨 call、identity/nonce 不符或旧 epoch 不获得接入。
SID 绑定必须限定账户、call 和角色，不能靠“有一个格式正确 SID”完成清理。

发出 token 之前，预算和 intent 已持久提交；签名完成之后，还须先提交该次
grant、join 绑定/摘要、签发结果和期限，才能交付 HTTP 响应。不能等 SDK 已
connect 才首次记账。准备中撤销后不交付许可，但已经开始的 reserve/sign 操作
仍需按原幂等键核对和清理；关闭浏览器不能取消其持久责任。

`assertCurrent()` 是现有接口的同步当前许可检查，不能用启动时读到的数据库
快照、READY 布尔或异步 Promise 替代。真实适配器如何维持可撤销的当前许可、
处理存储不可用与版本冲突，仍须设计和验收。每次 await 之后及最终 token 写出、
join、bridge 就绪、dial、媒体/字幕输出前均重查授权；这不使外部异步操作自动原子。

## 事务阶段与恢复用例

“当前证据”指基线的离线路由/单元测试，全部使用显式 fake；具体测试数量以
`PROGRESS.md` 和精确 commit CI 为准。右列中的崩溃/重启用例尚未实现或验收。
核对来源为 [Voice 许可测试](../tests/cloud-voice-join.test.ts)、
[授权 manager 测试](../tests/owned-session.test.ts)、
[本机线路清理回归](../tests/solo-session.test.ts) 和
[真实 router 的模拟依赖测试](../tests/cloud-phone-integration.test.ts)。

| 阶段或状态 | 必须提交的原子事实 | 恢复后的预期 | 当前证据与后续 fixture |
| --- | --- | --- | --- |
| `RESERVING` / reserve 结果未知 | 幂等操作键、授权绑定、预算请求与 call 创建 intent 的可追踪关系；成功后一次提交 reservation 和 intent | 按相同键核对权威结果；无法确认时拒绝 token/join/新通话，不盲目再 reserve | 当前：reserve 抛错/拒绝、坏接口会阻断。后续：事务提交后丢响应，重启只认同一 reservation；事务前崩溃不产生孤立预留 |
| `RESERVED`，尚未签发 | 已提交预算和 intent，未签发事实及版本 | 重新核验当前登录/lease；失效则安全回滚或进入清理，不恢复旧控制权 | 当前：等待 reserve 时撤销，signer 不开始。后续：预留后重启、原 lease 过期，既不签发也不重复扣预算 |
| `SIGNING` / 签发或交付结果未知 | 签名操作键、授权摘要、可能产生票据的最晚有效期限，在调用 signer 前记录 | 保留可能已签发的责任；不把 HTTP 断开或 signer 超时解释成票据不存在，不再发第二份新授权 | 当前：准备/最终发送前撤销不交付 fake token。后续：签名后、HTTP 写出前/后分别崩溃，恢复仍持有原签发 intent 与窗口 |
| `JOIN_ISSUED` / `JOIN_CONSUMED` | 一次票据绑定；消费状态与合法 local SID 一次提交 | 未消费的旧票据只允许按已记录责任拒绝/清理；已消费同 SID 可重试，新 SID 不可再拨出 | 当前：一次 join、同 SID replay、跨 call/重复 connect 拒绝。后续：join 消费提交后回调响应丢失，重启重试不生成第二腿 |
| `REMOTE_CREATE_PENDING` / `UNKNOWN` | remote 创建 intent 和操作键在供应商调用前提交；SID 返回或合法回调后持久绑定 | 核对未知创建，合法晚到 SID 进入 cleanup-only；供应商没有幂等 create 时不假设重试安全，不自动盲目重拨 | 当前：await create 期间结束/撤销后回收迟到 SID，未知角色阻断停机。后续：供应商接受后本进程崩溃，重启通过合法回调/权威查询找到同一腿 |
| `ACTIVE`，并发终态回调 | 各腿 SID/终态证据按版本或条件写入；终态单调，重复回调幂等 | 一腿终止触发另一腿清理；乱序旧非终态不能复活通话，错误账户/nonce/SID 不改变记录 | 当前：签名/绑定校验、并发结束与合法迟到回调保留。后续：两个 worker 同时处理终态/清理完成，只结算一次；重启后重复回调仍不复活 |
| `ENDING` / `CLEANUP_PENDING` | 结束 intent、停止新 admission、所有已知 SID 的清理待办及未知角色一次记录 | 无需新登录继续独立挂断与有限重试；新 SID 到达须追加待办，不能用旧“全部完成”快照覆盖 | 当前：同步结束先停媒体，独立两腿清理；失败保持 busy。后续：挂断接受后崩溃、单腿失败、新 SID 与完成事务竞争，恢复仍有完整待办 |
| `LINES_CONFIRMED` / `RELEASE_PENDING` | 全部已知腿确认结束、未知创建已核对、release 操作键与结算状态 | release 重试只一次改变 admission 占用；预算责任和 callback 记录继续保留到窗口结束 | 当前：清理确认后 release，失败阻断并可安全重试。后续：release 提交后丢响应，重启不重复退款或抹去迟到 SID 责任 |
| `LIABILITY_CLOSED` | 已知腿终止、未知创建消除、所有可能票据及供应商迟到窗口结束、预算结算已确认，条件写入最终版本 | 才能关闭剩余责任、结算未用预算并按保留策略归档；重复旧回调不能授予新连接 | 当前：仅进程内 tombstone 保留，不证明此状态。后续：票据有效期内迟到 local SID 仍清理；窗口前不得退款，窗口后按权威证据只结算一次 |

供应商回调始终先验证签名、账户及原 call/role/nonce/identity/SID 绑定，之后才
能登记合法迟到 SID 或改变清理状态。拒绝一个未经授权的浏览器操作，不能赋予
它清理别人的通话的能力。已签名合法回调即使 lease 失效，也须被责任记录接受
为 cleanup-only；认证失效不是丢弃 SID 的理由。

`release()` 目前表示释放 admission 占用，**不代表退款、journal 删除或责任归零**。
即使已知两腿结束，曾发出的 JWT 在有效期内仍可能产生迟到 browser SID，
供应商回调也可能延后。真实端口须明确 JWT 到期、供应商重试/接纳窗口和所有
UNKNOWN 的核对规则；不能自造一个短等待后宣布安全。允许提前释放单通占用时，
仍须保留残余预算责任和可恢复 callback/cleanup 记录。退款不得早于责任结束；
未确认线路清理或 release 仍拒绝下一通。当前短票据上限不证明供应商窗口已结束。

## 重启与停机

恢复启动先拒绝生产 token/join/dial，加载未完成事务和未关闭责任，增加/失效
旧 controller epoch，并停止恢复任何旧浏览器写权限。epoch/fencing 版本必须
来自已提交的恢复记录，不能每次进程启动从零重用。核对 reserve、签发、两腿
创建和清理 UNKNOWN，按已提交 intent 继续安全清理；记录缺失、存储不可读或
供应商结果无法核实，均保持 admission blocked。SSE 重连只读取当前状态，不续租，
页面刷新也不能凭旧 tab ID 重新取得控制能力。

正常停机先停止新 admission、持久接受结束 intent、停止媒体，再清理线路和
保留未完成责任；只有权威确认的停机结果才可称安全。进程退出、HTTP 200、
socket 关闭或容器强杀都不证明供应商线路终止。强杀后必须依赖后续恢复者接手，
不能因“本进程内存清空”解锁下一通。

实际存储验收须使用同一真实适配器，在两个独立进程间注入上述崩溃点；第二个
进程只读取已提交记录来恢复，不保留第一个进程的对象/数组，不用内存 fake
冒充重启。fixture 可以继续用 fake provider/signer、禁止外网及真实 JWT，但须
分别证明事务提交/回滚、重复响应、并发版本冲突、备份恢复和 UNKNOWN 阻断。
这组验收尚未实施，不属于本次网页接线的完成条件。

## 最少上线输入与停止点

本轮提交和精确 CI 完成后，停在以下真实部署输入门槛；不自动开始新的模拟
里程碑，不创建资源或凭据、不改变 Node/供应商，也不解除 cloud guard。

| 待确认或提供 | 最小输入 |
| --- | --- |
| 已验证登录方案 | 用户确认复用的登录/当前会话来源、受保护 cookie 的签发/撤销责任及单人账户范围；当前没有真实身份提供方选择 |
| 持久存储及恢复责任 | 确认可用的存储位置与事务能力、备份/恢复方式、执行恢复和未知供应商结果核对的责任人/进程；没有默认新数据库或配置 |
| 固定云入口及签名配置 | 确认固定 HTTPS/WSS 入口、单实例 warm 运行位置及代理/停机责任；核对既有公开账户/号码/应用标识。真实会话与 Voice signer 所需密钥必须另经批准注入运行环境，不在聊天、仓库或浏览器 fixture 中提交 |
| Pocket 既有材料 | 提供已审核的完整 Python 依赖 freeze/包完整性材料及匹配模型、Michael 状态、tokenizer 和本地 YAML；版本/哈希说明与 npm lock 不是完整 Python freeze，也不是资产本体。现状见 [Pocket 材料阻塞](CLOUD_POCKET_RUNTIME.md#当前材料阻塞) |

材料齐备和方案确认后仍需单独验收真实登录、签名、持久恢复、Linux warm 及
浏览器麦克风到普通手机通话。固定 Pocket Michael 出程、英文原声回程与逐句
原文/中文字幕配对不变；自然度、数字否定、长期播放积压及人耳延迟仍待实测。
