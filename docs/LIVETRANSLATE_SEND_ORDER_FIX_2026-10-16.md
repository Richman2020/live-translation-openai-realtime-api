## 确定缺陷和最小修改

1. **发送状态与背压。** e31把非OPEN和>1MiB合并，append返回即被称作已提交，且发送回调未形成串行进度。新增电话专用单写入泵：PCM待完成最多64000字节（16k PCM16两秒，含in-flight），wire待发另受原1MiB约束，socket高缓冲只在原上限下等待恢复，最老未完成帧最多2000ms。恢复后FIFO继续；满、到期、关闭或真实写错均显式失败，停止积压，不丢帧继续、不重试/重连、不扩大上限。成功回调也检查绝对期限，防止timer尚未派发时迟到回调绕过。两秒是发送等待保护，不是通话总时长。
2. **发送证据。** 区分 accepted、started、written、waiting、failed、cancelled、closed；记录安全枚举、状态、缓冲/待发字节、递增序号、队列等待和回调耗时、关闭码。计数明确分为客户端接收和本地socket回调完成；后者也不代表供应商收到。一般诊断节流，故障/关闭/取消不节流；每源事件保留最新accepted/written累计量。诊断观察者错误不能覆盖transport首因或改变电话状态。两层白名单拒绝正文、音频、provider ID、URL、认证头及任意错误文字。
3. **同方向译文与音频共同排序。** 精确e31的人工对照：已知A先、B后，B响应先返回时，原代码文本和音频均按[B,A]发布，确定为可复现缺陷，但不是本次真实帧重现。新电话路径按已准入VAD source offset及稳定同offset序号，共用文字/PCM门控；当前句首包照常流出，不等全文。后句等待前句源定稿/端点及已绑定响应完成，保持句段/响应身份；未知早响应不能被后句越过。同源多个响应仍按其创建顺序，供应商未提供更细可靠原句顺序时不编造。
4. **有界迟到与清尾。** 仅已到达且被阻塞的输出启动独立5秒重排等待；不是静音或整通电话计时。到期显式 `SOURCE_ORDER_TIMEOUT`；前沿推进后真正新到旧源输出显式 `SOURCE_ORDER_STALE`，不倒序补播、不静默丢句。已完成重复事件不重播，合法空响应可收尾；非空文字无要求的音频仍保留原严格错误。abort清理所有等待与残留PCM。完成元数据新增output item数量、译文字数、曾见音频布尔值，以区分下次空响应问题；不存正文。
5. **电话与翻译生命周期。** 保留真正协议/身份/会话/发送错误全停翻译的明确策略；原声和手动挂断继续。当前共享状态只有全局translationStopped，未实现分方向降级，不能简单吞掉remote错误假装local健康。持续背压/关闭仍可能全停，但页面通过持久owner快照/SSE显示“电话仍在进行·翻译已停止”，提示保留原声、手动挂断；真实媒体断开仍两腿清理。没有取消必要保护或新增通话金额/固定总时长上限。

跨方向真实发言时序**仍有限制**：原source.at是供应商事件首次到达应用的时间，不是声学起点，延迟到达的remote仍可能在页面排后。同方向已知源句的文本/音频倒序已修；没有可信offset到原始媒体时钟映射前，不给remote一律减20秒，也不声称已恢复整通真实对话先后。新增accepted/written/offset证据用于下一次定位；显示先后不能替代声学验收。
